用纯 Python 标准库写一个本地音频处理工具

发表于2026-08-24|更新于2026-08-24|编程

想做什么

手头有一批不同格式的音频文件，想统一转成 mp3。不想装一堆依赖，也不想把文件传到任何在线服务——最好是双击一下、浏览器打开、拖进去就能转的本地小工具。

于是就有了这个项目：一个零第三方依赖的本地 Web 工具。后端只用 Python 标准库，前端纯原生 HTML/JS，转码交给 ffmpeg。整个流程数据不出本机。

整体架构

前端和后端通过几个简单的 HTTP 接口通信，后端跑在本机 127.0.0.1，只有自己能访问。

后端：只用标准库搭 HTTP 服务

没装 Flask、没装 FastAPI，直接基于标准库的 http.server。

2. 静态文件服务 + 目录穿越防护

前端页面就是几个静态文件，直接读出来返回。但不能直接把用户传来的路径拼上去，否则 /../../etc/passwd 这种目录穿越就能读到任意文件：

交给 ffmpeg 转码

转码用子进程调 ffmpeg，输出 320k 的 mp3：

几个值得说的参数：

  • -map 0:a:0 -vn -sn -dn：只取第一条音频流，丢掉视频、字幕、附件，转纯音频。
  • -codec:a libmp3lame：指定用 LAME 编码器出 mp3。
  • -b:a 320k：目标码率。

ffmpeg 是个独立的二进制，单独放一个 bin/ 目录，程序启动时按「显式路径 → 项目自带 → PATH」的优先级自动找，找不到就给出友好提示。

踩过的坑

  1. Windows 控制台打不了 ✓——默认 GBK 编码，一 print emoji 就 UnicodeEncodeError。解决：sys.stdout.reconfigure(errors="replace")，打不出来的字符自动替换成 ?，不崩了。
  2. 中文文件名下载变乱码——要用 RFC 5987 的 filename*=UTF-8''...，而不是老的 filename=。
  3. 忘了做目录穿越防护——静态文件路径必须 resolve() 后校验范围，否则能被读到任意文件。
  4. createObjectURL 忘了释放——批量下载会内存泄漏，记得 revokeObjectURL。
  5. 文件名带路径——上传文件名要 pathlib.Path(name).name 剥干净，否则写临时文件时可能写到别的目录去。

下一步

  • 用 PyInstaller 打包成单个 .exe，双击就用，不依赖 Python 环境。
  • 前端加个并发上限（比如同时最多 2 个），大批量时更快又不压垮本机。
  • 加个任务队列，转换中关页面也不丢进度。

这次最大的收获是：不装任何框架，光靠标准库也能搭出一个体面的本地 Web 工具。http.server 加 socketserver 完全够用，剩下的就是几个边界细节（路径、编码、文件名）磨平。工具全程跑在本机，处理的是自己本地的文件，数据不出一台电脑。
