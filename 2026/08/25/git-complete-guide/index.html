Git 操作完全指南：从增量下载到团队协作

发表于2026-08-25|更新于2026-08-25|学习

Git 是每个程序员绕不开的工具。它管的不只是「代码备份」，而是怎么记录每一次改动、怎么追回错误、怎么和别人协作。这篇文章尽量讲透它，从最基础的日常操作，到别人改了代码你怎么只拿增量部分（以及怎么避免第一次克隆超大仓库），再到团队里怎么合代码、怎么救回误删的东西。

全程有命令示例和解释，当手册随查随用也成。

一、先搞懂 Git 的三个区和一个链

很多人被 Git 绕晕，是因为分不清「文件到底在哪」。记住三个区域就清晰了：

  • 工作区：你电脑上真实能看到的文件。改完不会自动进 Git。
  • 暂存区：git add 把「要提交哪些改动」先放进待办清单。
  • 本地仓库：git commit 把暂存区的清单正式记成一条历史记录（commit）。
  • 远程仓库：git push 把本地的提交同步到服务器，git pull/git fetch 把别人推的拉回来。

核心的一个链：每个 commit 都指向前一个 commit，head 指向最新那条。所有分支、合并、回退，本质都是「移动这个链上的指针」，而不是复制文件——这也是 Git 快、省空间的原因。

  • Changes not staged：改了但没 add

四、分支：Git 最核心的能力

分支的本质：一个可以移动的指针，指向某条 commit。main（或 master）是默认分支，你新建分支就是「另起一条平行线」，互不干扰。

合并怎么发生：分两种情况——

  • Fast-forward（快进）：当前分支没新提交，直接让指针往前移动到头，历史是一条直线，干干净净。
  • 三方合并：两边各自有提交，Git 把两个分支的改动「嫁接」出一个新的合并提交。如果两边改了同一文件的同一行，就有冲突，需要你手动定夺（见第六节）。

日常推荐流程：在 dev 上干活，git switch -c feature-xxx 开个功能分支，做完 git switch dev && git merge feature-xxx。

五、远程与协作：clone / fetch / pull / push

fetch 和 pull 的区别：

  • git fetch：把远程的新提交下载到本地，但不碰你正在改的代码。你想先看看、再决定怎么合，用这个。
  • git pull：下载 + 直接合并到当前分支。图省事用这个，但可能立刻产生冲突。

多人共用同一个分支时，改动前先 git pull 拿到最新，改完再 git push，push 被拒（别人比你高）就先 pull 再 push。

八、增量与部分克隆：别人改了代码，我只拿改过的部分

这是很多人问的「能不能只下载别人改的部分」。答案是：Git 本身就是增量传输的，而且是自动的。

8.1 有本地仓库时：pull 天然只下增量

你 git clone 过一次后，本地有一个完整对象库。之后别人改了并 push，你再 git pull / git fetch，Git 只传输你本地缺的那几个 commit 和文件对象，绝不会重新下载整个仓库。所以：

只要你已经 clone 过，git pull 就自动只拿别人改过的部分，不用任何特殊配置。

Git 的传输是按「对象」打包的，缺什么传什么，跟「全量/增量」无关——它天生就是增量的。

8.2 第一次克隆超大仓库：用参数少下载点

真正的痛点是不想「第一次就全量 clone」一个几个 GB 的 monorepo。三个参数按需省流量：

参数 作用 代价
--depth 1 只下载最新一次提交的快照 没有历史，git log 只剩一条
--filter=blob:none 下载全部提交和目录结构，但文件内容按需下载 用到哪个文件才下哪个，历史完整
--sparse 只检出指定目录 仓库其余部分不进本地

十、团队协作的标准流程（分支 + PR）

现在协作基本都走「功能分支 + Pull Request」：

  • 别人 review 后合并，分支可删。
  • 你的分支落后于 dev？在分支上 git merge dev 或 git rebase dev 同步。
  • rebase vs merge：merge 保留众人历史（会有合并分叉），rebase 把分支「垫」到 dev 顶端（历史更线性），各有取舍。团队有约定就按约定来。

十一、速查表

需求 命令
看状态 git status
暂存改动 git add .
提交 git commit -m "..."
看历史 git log --oneline
开分支并切换 git switch -c 分支名
合并分支 git merge 分支名
拉 + 合并 git pull
只拉不合并 git fetch
推送 git push
丢弃工作区改动 git restore <文件>
撤销最近提交（留改动） git reset --soft HEAD~1
撤销并抹掉最近提交 git reset --hard HEAD~1（慎用）
远程回退（补反向提交） git revert <hash>
暂存手头改动 git stash
找回误删 git reflog
只看改了哪些文件 git diff --stat HEAD..origin/分支

结语

Git 的核心不是你记多少命令，而是理解那个 「工作区 → 暂存区 → 提交 → 远程」的链和 「分支就是可移动指针」。懂了这两点，其余命令都是围绕它们转的便捷工具。

日常用熟：status、add、commit、log、switch、merge、pull、push 这八个就够绝大多数场景；reset、revert、stash、reflog 是用来救命的，记住它们的存在，关键时刻不慌。
