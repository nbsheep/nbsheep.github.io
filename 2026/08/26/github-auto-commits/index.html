用 GitHub Actions 每天自动提交，把 contribution 图填好看

发表于2026-08-26|更新于2026-08-26|编程
|浏览量:

想做什么

GitHub 个人主页那张 contribution 图，空一两天没事，但要是天天都是白的，看着总觉得差点意思。我又不想为了填格子去硬造「有意义」的提交——那样更没劲。

所以就有了这个：一个靠 GitHub Actions 定时跑的小东西，每天自动往一个专用仓库里随机提交 1–4 次。提交内容没有任何实际意义，只往一个日志文件里追加一行时间戳，也不碰任何真实项目。

为什么用 GitHub Actions

一开始想的是本机写个脚本，塞进 Windows 计划任务。但很快就否了：电脑得在计划时间开着，还得在本机存好 GitHub 的访问令牌，哪天重装系统或者换机器就断了。

GitHub Actions 没这些麻烦。工作流跑在 GitHub 的服务器上，只要仓库在，它就能按时跑，跟你电脑开不开机没关系。免费额度对这种几秒钟的小任务来说，根本用不完。

核心就是一个 workflow 文件

整个东西就一个文件：.github/workflows/daily.yml。逻辑不复杂，拆开看：

几个关键点：

  • cron: "30 12 * * *" 是每天触发。GitHub 的调度允许有几分钟到几小时的延迟，所以别指望它分秒不差，但一天之内总会跑。
  • $(( RANDOM % 4 + 1 )) 生成 1–4 的随机数，决定今天提交几次。
  • 每次提交只往 activity.log 追加一行时间戳，所以每次 git commit 都真的有内容，不是空提交。

踩过的坑

提交没进贡献图。 这是最坑的一个。GitHub 只把「账号关联邮箱」的提交计入贡献图。本机 git 配置里那个真实邮箱，如果没在 GitHub 设置里验证过，提交是算不进去的。解法是用 noreply 邮箱——去 GitHub → Settings → Emails 页面顶部能看到，格式形如 123456+username@users.noreply.github.com。它永远有效，还不暴露真实邮箱。

推送被拒，提示缺 workflow 权限。 用命令行 push 含 .github/workflows/ 的文件时，如果令牌是手动生成的，得额外勾选 workflow 这个 scope。我当时就是在这里卡了一下，重新授权补上权限才推上去。用网页直接上传文件倒是没这个问题。

私有仓库的绿点不显示。 contribution 图默认可能不统计私有仓库，得去设置里把 “Include private contributions on my profile” 打开。

一点实话

这玩意儿填出来的格子，跟「你干了活」是两码事。它就是个装饰，图个自己看着顺眼。真要拿 profile 给谁看，还是得靠那些真实项目里的提交——那个谁都糊弄不了，也没必要糊弄。

仓库我放在这了，想抄的直接拿去改：github-auto-commits
